# Tokenfire / 薪火 · 产品需求文档

版本：v0.1 草案  
日期：2026-09-09  
平台：macOS  
说明：产品名为工作名。本文中的首版范围与参数为建议默认值，可在原型验证后调整。

## 1. 产品定义

一把用 token 添柴的桌面篝火。用户使用 Claude Code 或 Codex 时，本地新增的 token 用量让火焰变旺、燃烧更久；停止使用后，火焰逐渐退成余烬。同时提供轻量的用量统计。

传播文案：**既然都在烧 token，不如真的生一把火。**

核心价值：让抽象的 AI 用量变成可感知的桌面陪伴，随手查看自己的使用节奏。

产品不主动发起模型请求来维持火焰。火势不代表工作质量、任务进度或 Agent 是否仍在运行。

## 2. 目标用户与场景

面向经常在 Mac 上使用 Claude Code、Codex 的开发者和创作者。

| 场景 | 用户期待 | 产品响应 |
|---|---|---|
| 开始使用 AI | 感知今天的工作开始了 | 捕获新增用量，点燃火焰 |
| 连续高频使用 | 获得及时而不打扰的反馈 | 火势逐渐增大，产生火星 |
| 暂停工作 | 桌面保留温暖的余韵 | 明火降低，转为余烬并自然熄灭 |
| 查看用量 | 快速知道今天用了多少 | 悬停查看摘要，点击展开统计 |
| 展示一天的使用情况 | 分享有辨识度的记录 | 生成“今天的火”图片 |

## 3. 首版范围

### 必须完成（P0）

- macOS 透明桌面悬浮火焰，可拖动、可隐藏、不抢焦点。
- 一种完整的火焰视觉风格，包含明火、火星、余烬、熄灭状态。
- 读取本机 Claude Code 与 Codex 可识别的用量日志。
- 用量变化驱动火势和燃料，具备平滑过渡与上限。
- 今日统计：总量、来源、输入 / 输出 / 缓存拆分、用量时间线。
- 菜单栏入口、数据源状态、基础设置。
- 本地存储、增量读取、重复记录处理。

### 首版增强（P1，不阻塞核心发布）

- “今天的火”分享卡，导出 PNG。
- 最近 7 天用量查看。
- 手动选择日志目录。

### 后续版本

- 刘海 / 灵动岛展示形态。
- 小组“围炉”：成员的小火共同组成营地。
- 多种皮肤、可选柴火声、额外数据源。
- 项目、模型维度的统计。
- API 等值费用估算。

首版不包含账号系统、云同步、排行榜、支付、额度查询、Agent 操作或完成通知。

## 4. 用户流程

1. 首次启动，简短说明用途及本地读取范围。
2. 自动发现支持的日志目录，显示每个来源的连接结果。
3. 初次导入今日历史用于统计；历史数据不触发大量添柴动画。
4. 在当前屏幕的可用区域展示小火堆；默认位置建议右下角，避开 Dock。
5. 首次捕获新增用量后点燃火焰；没有用量时保持未点燃状态。
6. 悬停显示今日摘要，点击打开统计面板。
7. 用户通过拖动调整位置，通过菜单栏控制显示、动画和设置。

未发现数据时，说明“尚未发现支持的本地用量记录”，提供重新检测入口。不得显示虚构用量。

## 5. 火焰机制

### 5.1 三个独立状态量

| 状态量 | 含义 | 视觉表现 |
|---|---|---|
| intensity：火势 | 最近一段时间的消耗强度 | 火焰高度、宽度、摆动幅度 |
| fuel：燃料 | 近期新增用量积累的燃烧储备 | 明火能够维持的时间 |
| emberHeat：余温 | 明火减弱后留下的热度 | 红炭亮度、缓慢呼吸的光晕 |

新增用量同时增加燃料和近期消耗强度。燃料随时间消耗，余温比火势更慢衰减。低火、小火、中火、旺火之间连续过渡。

### 5.2 建议初始规则

- 用最近约 60 秒的用量增量计算消耗强度，并平滑处理。
- 用非线性映射压缩大额用量，避免火焰瞬间占满屏幕。
- 燃料池设上限，建议最多储存约 15 分钟的燃烧量。
- 停止添柴后，火势在约 30–90 秒内明显回落；剩余燃料可维持小火。
- 燃料耗尽后进入余烬状态，建议在约 2–5 分钟内自然熄灭。
- 短时间收到多条日志时合并视觉反馈，限制火星数量。
- 首版使用固定映射参数；用不同强度的真实日志回放调参。

以上时间是体验调参起点，不是已验证的产品指标。

### 5.3 边界行为

- 新启动时，导入历史只更新统计，火焰等待新增用量。
- 隐藏火焰或暂停动画时继续采集；恢复时显示当前状态，不重放全部事件。
- 睡眠期间停止渲染；唤醒后按实际经过时间衰减，补读历史不产生爆发式添柴。
- 跨日仅切换统计日期，不强制熄火。
- 数据源报错时保留已有统计并显示异常，不能把错误当成零用量。

## 6–12

桌面交互、统计口径、数据源、分享卡、技术方案、性能与验收标准以会话原始 PRD 为准；工程实现按第 13 节顺序推进。

## 13. 实施顺序

1. **视觉原型**（当前已落地）：模拟低、中、高用量，完成透明窗口、火焰、余烬与拖动。
2. **单来源闭环**：接入一种真实日志，验证去重、用量变化、重启恢复与火焰映射。
3. **双来源与统计**：接入另一来源，完善口径、菜单栏、面板和错误状态。
4. **发布验证**：多屏、全屏、睡眠、能耗、签名公证；再补分享卡。
